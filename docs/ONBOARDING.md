# ONBOARDING — راه‌اندازی یک آرایشگر جدید

هدف: از «لینک اینستاگرام مشتری» تا «سایت دمو + دو ربات» در کمتر از ۵ دقیقه، بدون دیپلوی جدید.

## مسیر ۱: ویزارد پنل پلتفرم (فاز ۵)

`https://platform.<BASE_DOMAIN>` → «مشتری جدید»:

1. **برند:** نام نمایشی، slug (زیردامنه)، حالت (`solo` / `salon_central` / `salon_independent`)، هندل اینستاگرام، تلفن، آدرس، لینک نقشه، لوگو، ۳ تا ۶ عکس.
2. **خدمات:** نام، مدت، قیمت (چند پیش‌فرض آماده).
3. **ساعت کاری:** هفتگی؛ یا فعال کردن «اسلات دستی».
4. **بیعانه:** فعال/غیرفعال، شماره کارت، صاحب کارت، مبلغ ثابت یا درصد، مهلت پرداخت، متن سیاست کنسلی.
5. **ربات‌ها:** توکن تلگرام و بله (راهنمای BotFather داخل صفحه). وب‌هوک خودکار ست می‌شود.
6. **قالب و رنگ:** انتخاب بین سه قالب + رنگ اصلی؛ **پیش‌نمایش زنده** همان‌جا.
7. **متن‌ها:** اگر ماژول AI فعال و کلید تنظیم باشد، بیو/توضیح خدمات/SEO پیشنهاد می‌شود؛ همه قابل ویرایش.
   «ایجاد» ⇒ tenant با `status=demo` روی `slug.<BASE_DOMAIN>` بالاست. بعد از فروش: «فعال‌سازی» + (اختیاری) دامنه اختصاصی.

## مسیر ۲: CLI (فاز ۵)

```bash
pnpm tenant:create --file tenant.json
```

`tenant.json` همان فیلدهای ویزارد است (اسکیمای zod در `packages/core/src/onboarding/schema.ts`).

## چرا اینستاگرام خودکار خوانده نمی‌شود

API رسمی نیاز به اکانت بیزینسی + تأیید متا دارد؛ اسکرپرها مدام بلاک می‌شوند و اینستاگرام از ایران فیلتر است. پس هندل فقط به‌عنوان لینک استفاده می‌شود و عکس‌ها دستی آپلود می‌شوند (فچ خودکار پشت فلگ برای آینده).

## دامنه اختصاصی مشتری

مشتری یک رکورد CNAME از دامنه‌اش به `<BASE_DOMAIN>` می‌زند؛ شما در پنل پلتفرم دامنه را وارد می‌کنید؛ Caddy با on-demand TLS فقط برای دامنه‌های ثبت‌شده گواهی می‌گیرد (`/api/caddy/ask`).
